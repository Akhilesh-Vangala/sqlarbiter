# AI design

The provider-independent controller now uses **official anthropic.AsyncAnthropic** rather than urllib. It verifies the configured model, counts input tokens before generation, consumes typed streaming Messages events, feeds tool results back, validates the final decision, and records incomplete as well as successful runs. SQL calls execute through asyncio.to_thread; API requests enqueue work for a separate process.

Seven evidence tools are available: contract, describe, profile, lineage, changes, current_sql and query. finish submits the decision separately. describe reports the engine and pages schema metadata; profile computes bounded null/distinct counts. Queries return at most 100 rows/50 columns and mark truncated cells/rows. Source values/change text are data, not instructions. Injection resistance has not been evaluated against a broad adversarial corpus.

Budgets: eight model rounds; 24 evidence calls; at most three identical calls; 2,048 requested output tokens per round and 12,000 total output tokens; at most 16,000 counted input tokens per request and 64,000 counted input tokens across the investigation; 250 KB serialized provider body; 32 KB per tool result. The async investigation deadline is 240 seconds and parent-worker deadline 270 seconds. SDK timeout is 20 seconds, max_retries=1. Retries can add provider requests; these controls are not an exact dollar ceiling.

The SDK handles transport retries/typed SSE assembly; application validation still checks tool arguments, identities, decision fields and cited evidence. A finish containing evidence calls, invalid JSON/protocol responses, refusal/truncation, invented evidence or exhausted budgets fails. A provider failure is sanitized; failed trace/model metadata are saved. Reported usage is not a provider invoice, and incomplete streams may have unknown billed usage. Events logs contain types/timestamps only. OTel exports span names, durations and bounded metadata; prompts, SQL text, rows and API keys are not exported to Phoenix.

**Configuration is not live validation.** SDK protocol tests use local scripted HTTP responses; no live AI run or model-quality result exists yet. The retired claude-3-5-sonnet variants are unsuitable: [Anthropic retirement notice](https://platform.claude.com/docs/en/about-claude/model-deprecations). The private example selects claude-sonnet-5-5 from the [current model overview](https://platform.claude.com/docs/en/models/overview), subject to account availability checked at runtime. [Official async Python SDK](https://platform.claude.com/docs/en/cli-sdks-libraries/sdks/python).

The fixed baseline is deliberately contract-specific and knows the supported query strategies. Its perfect synthetic score establishes evaluation plumbing, not a need for learning. Compare strong live hosted models with matched tools/authority before investing in adaptation. The 38-case corpus still has limited fault/shape diversity. A learned evidence/action/stopping policy, LangGraph orchestration, supervised adaptation and ablations remain proposed; RL is gated on valid rewards and sufficiently diverse data.
